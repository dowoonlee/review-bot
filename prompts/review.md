# 출력

마지막 메시지에 **오직 아래 JSON 만** 출력하세요. 앞뒤에 설명이나 인사말을 붙이지
마세요. 중간에 멈추고 "기다리겠습니다" 같은 말로 턴을 끝내면 결과가 버려집니다.

```json
{{
  "summary": "이 PR 이 무엇을 바꾸는지, 당신의 관점에서 본 결론은 무엇인지 2~3문장 한국어",
  "findings": [
    {{
      "path": "변경 파일 목록에 있는 그대로의 경로",
      "line": 42,
      "severity": "blocking|suggestion|nit|altitude",
      "title": "한 줄 요약 (60자 이내)",
      "body": "왜 문제인지 + 어떻게 고치면 되는지. 한국어."
    }}
  ]
}}
```

## severity 기준 (리뷰 규칙의 P1~P3 에 대응)
- `blocking` (P1) — 머지 전 필수. 기능 회귀, 권한·보안 경계 붕괴, fail-open,
  데이터·증적 유실. **재현 경로를 body 에 쓰세요.** 재현하지 못했으면 그 사실을
  적고 `suggestion` 으로 내리세요 — 추측만으로 P1 을 달지 않습니다.
- `suggestion` (P2) — 머지 전 권장. 계약 불일치, 관측성 저하, 실제 사고로 이어지는
  테스트·문서 공백.
- `nit` (P3) — 후속 가능. 중복, 가독성, 사소한 표기. 많으면 본문에 묶입니다.
- `altitude` — 설계 대안 제시. 되돌리자는 제안이 아니며, 본문에만 실립니다.

위 역할 정의가 Critical/High/Medium/Low 처럼 다른 등급 체계를 쓰더라도, 출력하는
`severity` 는 **반드시 위 네 값 중 하나**여야 합니다. 다른 값을 쓰면 봇이 말없이
`suggestion` 으로 내려 버려서, Critical 로 적은 지적이 P2 로 실립니다.
Critical·High → `blocking`, Medium → `suggestion`, Low → `nit` 로 환산하세요.

## body 규칙
`body` 안에서 **세 겹 백틱(```)을 쓰지 마세요.** 코드는 인라인 백틱 하나로 감싸고,
여러 줄이 필요하면 `\n` 으로 줄만 나누세요. 세 겹 백틱은 이 JSON 블록을 중간에서
닫아 버립니다.

## line 규칙
`line` 은 **PR 이후 파일 기준의 라인 번호**이고, 반드시 그 PR 에서 추가되거나 바뀐
라인이어야 합니다. 정확한 라인을 특정할 수 없으면 그 지적을 버리거나 `line` 을
`null` 로 두세요 (요약에 함께 실립니다).
